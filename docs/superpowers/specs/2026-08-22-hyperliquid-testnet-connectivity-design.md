# Hyperliquidテストネット接続確認 設計仕様

## 目的

リポジトリ直下の `.env` に設定された `HL_test_wallet` と `HL_test_wallet_private_key` を使い、Hyperliquidテストネットへの公開API接続と署名付きAPI接続を確認する。検証では注文、送金、レバレッジ変更を行わず、Hyperliquid公式の `noop` アクションを一度だけ送信する。

## 配置と実行環境

成果物は `hyperliquid-ai-trader/`（当初名 `hyperliquid-testnet-research/`）に集約する。この中に `pyproject.toml`、README、`src/`、`tests/`、実行結果JSON、専用の `.venv/` を置く。秘密情報を含むルート `.env` は移動・複製せず、Git管理対象にも含めない。

## 接続確認フロー

CLIはルート `.env` を読み、二つの環境変数が空でないこと、ウォレットがEthereum形式のアドレスであること、秘密鍵を公式SDKが読み込めることを検証する。秘密鍵から導出した署名者アドレスと `HL_test_wallet` が異なる場合は、前者を承認済みAPIウォレット候補、後者を照会対象のマスターアカウントとして扱い、単純な不一致だけでは失敗にしない。

次にテストネットのInfo APIから市場メタデータと `HL_test_wallet` のユーザー状態を取得する。秘密鍵由来の署名者が対象ウォレットと異なる場合は `userRole` を照会し、署名者が `agent`、その紐付け先 `user` が `HL_test_wallet` と一致する場合だけ署名処理へ進む。不一致ならnonceを消費せず終了する。最後に公式 `hyperliquid-python-sdk` の `Exchange.noop(nonce)` を呼び、レスポンスの `status` が `ok` であることを確認する。`noop` は注文や資産を変更しないが、署名者のnonceを一つ消費する。

## 出力と秘密情報保護

標準出力と `results/connection_check.json` には、各検証項目の成否、テストネットURL、取得できた市場数、ユーザー状態取得の成否、署名者と対象アカウントが同一か、署名者の役割、対象への認可成否、`noop` の応答分類だけを保存する。秘密鍵、署名、ウォレットアドレス、API応答の残高・ポジション詳細、`.env` の内容は保存・表示しない。例外文に秘密鍵が含まれないよう、外部へ出すエラーは分類済みの短いメッセージにする。

## テストと成功条件

ネットワーク通信とSDKオブジェクト生成を境界インターフェースとして注入可能にし、単体テストでは環境変数の不足、不正アドレス、公開API成功、直接署名者、正しいagent紐付け、誤ったagent紐付け、`noop` 成功、`noop` エラーを再現する。成功条件は、全単体テストが通り、専用仮想環境から実行した実接続結果で対象ウォレットへの署名者認可、公開API、署名付き `noop` がすべて成功することである。外部API側が拒否した場合は接続不能と断定せず、HTTP到達、公開照会、署名者認可、署名検証のどの段階で失敗したかを分けて報告する。

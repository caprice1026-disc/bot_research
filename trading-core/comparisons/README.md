# NautilusTrader / existing core: scoped execution-accounting parity

## Verified result

Windows x86-64, CPython 3.12.16, NautilusTrader 1.231.0. The checked-in
`nautilus_parity_result.json` is generated by an actual offline BacktestEngine
run, not an inferred comparison. Two explicit tests passed, including a second
identical run. Four upstream Pandas `Timestamp.utcnow` deprecation warnings
were observed; they do not change the result.

Both engines consume the same seven-row synthetic timestamp / price / target
position tape. Policy: long open, add, hold, partial reduce, close, short open,
close. Nautilus uses a linear USDT-settled CryptoPerpetual, NETTING MARGIN
account, L1 quote book, market orders, zero latency, ample displayed liquidity,
zero bid/ask spread and 0.1% taker fee. Existing PositionAccount receives flat
OHLC points at the same prices with zero spread/slippage and the same fee.
The clock is milliseconds UTC converted exactly to nanoseconds for Nautilus.
Orders are submitted after each observed quote; immediate matching explicitly
uses `use_message_queue=False`. This is an idealized causal target tape, not a
claim that a completed candle can always be traded at its close.

All six normalized fills match exactly: event time, signed quantity, fill
price and fee. Final flat quantity and cash match. Independent arithmetic:
- Buy 1 @ 100 and 1 @ 110: average entry 105.
- Sell 1 @ 120: +15; sell 1 @ 90: -15.
- Sell short 1 @ 95 and buy 1 @ 85: +10.
- Turnover 600; fees 0.600 USDT; gross PnL 10; net PnL 9.400.
- Initial cash 10000; final cash 10009.400 USDT.

The report contains the SHA-256 of the shared data tape and package/Python
versions. Stable normalized economic results are compared, not engine-generated
UUIDs or wall-clock diagnostics. The environment is pinned in requirements.lock;
the lock is a version snapshot, not a cryptographic supply-chain lock.

## Reproduce (PowerShell, from repository root)

Use an isolated Python 3.12 environment, never a live trading environment:

```powershell
py -3.12 -m venv trading-core/comparisons/.venv
trading-core/comparisons/.venv/Scripts/python.exe -m pip install -r trading-core/comparisons/requirements.lock
trading-core/comparisons/.venv/Scripts/python.exe trading-core/comparisons/nautilus_parity.py --write
trading-core/comparisons/.venv/Scripts/python.exe -m pytest trading-core/comparisons/test_nautilus_parity.py -q -p no:cacheprovider
```

If Python 3.12 is not installed, install it explicitly before those commands.
This checkout's test environment was provisioned with uv 0.13.9 and its managed
CPython 3.12.16. The ignored `.bootstrap`, `.python` and `.venv` directories are
local tooling, not repository deliverables. The comparison is opt-in and does
not add Nautilus as a runtime dependency of trading-core.

## What this does NOT establish

The synthetic fixture does not evaluate real data or strategy profitability. It is a small golden
fixture for fill accounting and adapter semantics, not wholesale validation of
either engine. Funding, liquidation and gap ordering, live venue maintenance
margin tiers, inverse contracts, rounding-edge quantities, OHLC intrabar
ambiguity, L2 taker market impact, maker queue position, latency, cancellation,
partial fills, Polymarket settlement and realistic data availability remain
outside this comparison. In particular neither L2 nor maker accuracy can be
inferred from these ideal L1 executions. No network orders or wallet operations
occur in this script. Future historical comparisons must share source hashes,
availability timestamps, venue rules and strategy decisions, and report
unsupported events instead of silently dropping them.

HftBacktest was separately executed on a synthetic maker-latency fixture; see [hft/README.md](hft/README.md). Real-book queue calibration remains unverified.
Freqtrade can inform experiment/report UX; it is not a third parity oracle in
this test.

## Real BTCUSDT OHLCV: same-adapter extension

`real_ohlcv_parity.py` uses the same two adapter functions, leaving the original
synthetic fixture intact. It reads the existing `market_1m.npz` only, without
writing into the source dataset. Before inspecting window prices/results, the
window was fixed to 2025-10-01 01:00:00 UTC inclusive through 02:00:00 exclusive
(60 consecutive one-minute bars). Source SHA-256:
`021af1f7ad33153ea20870287cdef75d28b8522f7013f69073bf9d15d3ea860f`.
The output also hashes the selected OHLCV window and shared execution tape.
The source is the existing Binance research dataset; its upstream archive
provenance has not been independently re-downloaded or audited by this script.

Fixed policy: every five minutes, the preceding completed bar's close versus
open chooses +0.010 or -0.010 BTC. An opposite existing position goes flat first;
it can open the new direction on a subsequent decision. Hold between decisions.
The final minute closes by a predeclared schedule. Both adapters receive the
same target and execute at the next bar's open, not at the signal bar's close.
Every signal source timestamp and target is saved in `decision_audit`.

This is a **zero-spread L1 proxy derived from real OHLCV, not recorded quotes or
an order book**. Flat OHLC points go into core; equivalent bid=ask open quotes
with ample synthetic liquidity go into Nautilus. Zero latency assumes the prior
close is available exactly at the next open, an optimistic execution boundary.
It must not be described as live-achievable execution. Costs are fixed at 0.1%
per fill, not an assertion about the user's exchange fee tier. The chosen
window has no funding events; the script rejects a window containing one rather
than silently discarding funding.

Verified: **10 fills**, exact timestamp / price / quantity / per-fill fee match.
Both final cash balances are **9988.845889 USDT**, fees **11.429111**, gross
realized PnL **0.275**, net PnL **-11.154111**, and both end flat. Cash, fees and
PnL absolute tolerance is declared as 0.0000001 USDT for currency rounding;
observed differences were all exactly zero. Both engines were run twice and
normalized results matched within each engine. The original synthetic tests
were rerun: 2 passed (4 upstream Pandas deprecation warnings).

Reproduce after installing the root comparison requirements above:

```powershell
trading-core/comparisons/.venv/Scripts/python.exe trading-core/comparisons/real_ohlcv_parity.py --source ../bot_research/binance-btcusdt-futures-research/data/paper_validation_20261031/market_1m.npz --write
```

Supply `--source` with the matching local file when repository placement differs.
Data is not copied into Git. The checked-in `real_ohlcv_parity_result.json`
contains the result, per-engine fills and source/decision manifest. No live
execution, realistic spread/depth, liquidation, maker queues, strategy tuning
or out-of-sample performance validation is claimed. This short window tests
adapter agreement on real prices, not economic viability.
